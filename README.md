# 麦麦点单助手 · mcd-assistant

> 一个基于麦当劳官方 MCP Server 的 WorkBuddy Skill —— 让 AI 真正帮你把麦当劳点完，而不是只会念菜单。

身材管控期也想吃麦当劳？加班到深夜只想来一份巨无霸？企业团餐预算不好算？party 场次约不上？
**麦麦点单助手**把麦当劳 35 个 MCP 工具编排成一条条可靠的使用路径，并替你守住钱包和账户安全。

---

## 这是什么

麦当劳 MCP 提供了 35 个能力完整的工具，但**裸调用的门槛很高**：

- 四种取餐方式（到店自取 / 得来速车道 / 麦乐送外送 / 企业团餐）对应 3 个联动参数，传错直接报错
- 价格字段单位是「分」，直接展示会差 100 倍
- 写操作（下单、领券、兑换、抽奖）容易误触

本项目把这些**隐性规则固化成 Skill**，让 AI 不再每次重新推导，而是稳定地走通全流程。

| 能力 | 说明 |

## 三重安全护栏

**1. 写操作全部需确认**
下单、一键领券、积分兑换、抽奖、取消订单、新增地址——每一项在执行前都会完整复述关键信息，等你明确点头才继续。「试试看」「如果可以就抽」**不算**确认。

**2. 不编造任何数据**
门店、餐品、价格、优惠券、积分、订单号、奖品一律来自工具真实返回。营养数据中的异常项如实告知，不编造合理值。

**3. 分→元强制换算**
价格字段单位为「分」，展示前一律换算为「元」，并在确认环节复述应付金额。

## 安装方法

### 前置条件

- WorkBuddy（[官网](https://www.workbuddy.cn)）
- 已申请到麦当劳 MCP Token（[open.mcd.cn/mcp](https://open.mcd.cn/mcp) → 手机号登录 → 控制台 → 激活 → 同意服务协议）

### 第一步：配置 MCP 连接

打开 WorkBuddy → 左侧边栏【专家·技能·连接器】→【连接器】页签 → 右上角【自定义连接器】→【配置 MCP】，填入：

```json
{
  "mcpServers": {
    "mcd-mcp": {
      "type": "streamablehttp",
      "url": "https://mcp.mcd.cn",
      "headers": {
        "Authorization": "Bearer YOUR_MCP_TOKEN"
      }
    }
  }
}
```

> ⚠️ 务必把 `YOUR_MCP_TOKEN` 替换为你的实际 Token，然后点击【保存】。

> 💡 也可直接编辑 `~/.workbuddy/mcp.json` 写入同一份配置。仓库中的 `mcp-config.example.json` 使用 `${MCD_MCP_TOKEN}` 环境变量占位符，**不含任何真实凭证**，可安全提交。

保存后回到【自定义连接器】，将 **mcd-mcp** 启用。

### 第二步：安装 Skill

将 `SKILL.md` 放入你的 Skill 目录：

- **用户级**（推荐，全局可用）：`~/.workbuddy/skills/mcd-assistant/SKILL.md`
- **项目级**：`{项目目录}/.workbuddy/skills/mcd-assistant/SKILL.md`

或直接在 WorkBuddy 中说「帮我安装这个 Skill」并指向 `SKILL.md`。

### 第三步：验证

在对话框输入：

```
看看附近有哪些麦当劳门店
```

若能正常返回门店列表，即安装成功。

## 使用示例

### 场景一：十分钟搞定一顿午饭

```
我附近有麦当劳吗？帮我点一份巨无霸套餐
```
> 助手会：定位门店 → 拉取菜单 → 查该店可用券 → 算价 → 复述门店/餐品/券/金额/取餐时间 → 等你确认 → 下单 → 返回支付链接

### 场景二：减脂期点餐

```
我想减肥，有没有热量低一点的麦当劳套餐？预算 40 块
```
> 助手会：查营养数据 → 按能量与蛋白质筛选 → 结合实时在售商品给出搭配 → 标注能量、蛋白质、脂肪、碳水、钠 → 说明「实际以门店出品为准」

### 场景三：企业团餐

```
公司 30 人聚餐，预算 3000，看看能怎么配
```
> 助手会：先问清预算与人数 → 查可配送门店 → 查满减满折规则 → 按人均预算搭配（附不同预算档位的搭配结构）→ 查助餐服务 → 试算价格 → 确认后下单

### 场景四：积分抽奖

```
我有多少积分？现在有什么抽奖活动？
```
> 助手会：查积分 → 查活动信息 → 展示奖品列表与**本次实际消耗** → 等你明确确认后才抽奖

### 场景五：查订单

```
帮我查一下订单 1030108270000795xxxxxxxxxxxx
```
> 助手会：查订单状态与配送进度；也可继续查该订单的满意度答卷与关联奖券

## 设计原则

1. **规则优先于即兴** —— 参数矩阵、key 传参规则等隐性约束写死在 Skill 里，不依赖模型临场推理。
2. **确认前置** —— 所有影响账户与钱的操作，一律先复述再执行。
3. **数据诚实** —— 营养表存在脏数据（重复条目、数值倒挂、零值），如实标注而非粉饰。
4. **失败可解释** —— 工具报错时说明原因并给出替代路径，不用记忆冒充真实结果。
