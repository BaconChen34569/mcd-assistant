# Demo 素材说明

`README.md` 首屏引用 `docs/demo.gif`，**该文件尚未提供**。

图片加了 `onerror` 隐藏属性，所以素材缺失时不会显示破图，页面观感不受影响。

## 建议录制规格

| 项 | 建议值 |
|---|---|
| 宽度 | 880 px |
| 时长 | 6 秒以内，循环播放 |
| 格式 | GIF，或 WebP（体积可再减约 60%） |
| 落盘路径 | `docs/demo.gif`（或 `docs/demo.webp` 并同步改 README 中的路径） |

## 建议演示的内容

同一屏内并排呈现「未询问」与「已询问」两种结果，让人一眼看出差异：

| 画面 | 内容 |
|---|---|
| 左半屏 | 输入「我想减肥，有没有热量低一点的套餐？预算 40 块」→ 直接给出通用推荐（热量 347 kcal） |
| 右半屏 | 同样的问题 → 助手先追问健康状况与进食场景 → 用户答「尿酸高 + 正餐」→ 推荐表切换为麦乐鸡 + 玉米杯 + 纯牛奶（约 395 kcal / 钠 496 mg） |

这正是本项目与其他同赛道项目最大的差异点：**答案会因人而异**。

## 录屏注意事项

- **务必遮蔽 MCP Token**，以及请求头中的 `Authorization` 字段
- 只展示业务信息：门店、餐品、价格、营养表字段
- 不要展示 `.workbuddy/` 目录下的本地记忆内容
- 建议用纯色背景 + 放大字体，终端深色主题下更易辨识

## 备选方案

如果不方便录屏，README 首屏的「文字版演示」折叠块已经能完整表达核心差异，可直接删除上方的 `<p align="center">` 图片段落。
